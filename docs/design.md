# HD100 固件设计

本文汇总需求与资源，给出完整固件的架构和分阶段计划。硬件事实见 [hardware.md](hardware.md)，这里只引用结论。
协处理器暂不使用(PC15 常高，让出 SPI 总线),后续方向见第 7 节。

## 2. 需求

### 2.1 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| F1 | 标准 CCID,pcscd / Windows 免驱(加入 libccid 设备表后) | 已有 |
| F2 | 非接：现有能力保持;M1/NTAG 伪 APDU 与 ACR122U 兼容 | 已有 |
| F3 | 接触：正面卡座 T=0 **与 T=1**,PPS,短 APDU(加命令链)| 高 |

| F6 | 屏：待机状态(各卡座、USB)、事件提示、PIN 输入界面、主机下发的文字 | 高 |
| F7 | 磁条 2/3 轨 → HID 键盘(现有格式不变)| 已有 |
| F8 | 厂商控制通道：显示文字、蜂鸣、读按键、设置、诊断计数、版本 | 中 |
| F9 | 本机菜单(F1–F3):对比度、提示音开关、键盘模式、设备信息、进入升级 | 低 |

| F12 | 键盘透明输出：空闲时按键作为 HID 键盘按键直接送主机 | 中 |
| F13 | 以后:PIN / 按键经协处理器加密(待协处理器研究清楚，见第 7 节)| 待定 |

### 2.2 非功能需求

- **任何一路卡操作都不能让其他功能停摆**:USB 枚举 / 控制请求、另一个 CCID 接口、磁条、键盘、屏必须在
  接触卡长命令(卡上生成密钥可达数秒)期间继续工作。当前阻塞式接触驱动违反这一条，是首要改造点。
- 每个外设缺失或无响应时都只影响自身：报错、给主机合理的状态码，不 panic、不卡死。
- PIN 不经过主机、不出现在日志中，用完即清零；PIN 输入期间按键不送到 HID。
- 看门狗兜底(IWDG 2 s)。
- 产品构建 `DEFMT_LOG=off`;调试构建保留 RTT 日志。
- 序列号用芯片 UID(0x1FFFF7E8),多台可区分。

## 3. 资源汇总

### 3.1 外设占用

| 资源 | 使用者 | 备注 |
|---|---|---|
| USB FS | embassy-usb | PMA 512 B,见 3.4 |
| TIM3 CH2 / CH3 | 卡座 1 / 卡座 2–5 时钟 4 MHz | CH3 被 4 个 PSAM 座共用 |
| TIM4 | embassy 时间驱动 | |
| SysTick | M1 读卡器随机数 | 自由运行 |
| DWT CYCCNT | iso7816、idsam、thm3060 的忙等定时 | |
| USART2 | P5 模块 | |
| IWDG | 看门狗(新增) | |
| **空闲** | TIM1、TIM2、USART1、USART3、SPI1/2、I2C1/2、DMA1、ADC、RTC/BKP | |

值得注意的空闲资源:
- **USART3_RX = PB11 = 卡座 1 I/O,USART3_CK = PB12 = 卡座 1 RST**。卡座 1 收方向可以用硬件 USART
  (9 位 + 偶校验，波特率 = 卡时钟 / etu)接收，免去位模拟，见 5.3。
- TIM2 全重映射后 CH4 = PB11,可做卡座 1 起始位输入捕获。

### 3.2 中断与 EXTI 线

| 向量 | 来源 | 处理时长 |
|---|---|---|
| USB_LP_CAN1_RX0 | USB | 短 |
| EXTI9_5 | 磁条 2 轨时钟 PA9(EXTI9)| 几 µs |
| EXTI15_10 | 磁条 3 轨时钟 PC10(EXTI10)+ P5 模块 PB15(EXTI15)| idsam 收一整帧(毫秒级)|
| USART2 | P5 模块 | 短 |
| TIM4 | 时间驱动 | 短 |

EXTI 线按引脚号共用，接触卡 I/O 的 EXTI 线：卡座 1 PB11→11、2 PC7→7、3 PC9→**9(与磁条 PA9 冲突)**、
4 PB13→13、5 PC12→12。卡座 3 不能用 EXTI 检测起始位。

### 3.3 时序冲突矩阵

| | 磁条 bit(≈300 µs 一位)| idsam I2C(晚 500 µs 丢帧)| 接触字符(93 µs etu 时 1.2 ms 关中断)|
|---|---|---|---|
| 磁条 | — | 同一向量，idsam 收帧期间 3 轨丢位 | 关中断期间丢位 |
| idsam | | — | **互斥**:谁打断谁都会丢数据 |

结论：
1. idsam 与接触卡收发用一把"实时锁"互斥(一次长的模块命令约 1 s,期间接触命令排队等待)。
2. 接触字符的临界区改用 BASEPRI 而不是全关中断，留下磁条 EXTI(ISR 几 µs,对 ≥ 20 µs 的 etu 无影响);
   etu < 20 µs 时才全关。
3. 模块命令期间刷卡 3 轨可能出错(LRC 能检出，主机收到 `;E?`),接受。

### 3.4 USB 端点与包缓冲

| 端点 | 用途 | PMA |
|---|---|---|
| EP0 | 控制 | 64 + 64 |
| 接口 0 | CCID 非接 bulk OUT/IN + int IN | 64 + 64 + 8 |
| 接口 1 | HID IN | 16 |
| 接口 2 | CCID 接触 bulk OUT/IN + int IN | 64 + 64 + 8 |
| BTABLE | | 64 |
| 合计 | | ≈ 480 / 512 B |

**不能再加 64 字节端点**。厂商控制通道(F8)走 HID 接口 1 的特性报告(feature report,只用控制管道),
不加接口、不占 PMA;Linux 下经 hidraw 访问，免驱(bp8903 的诊断报告同样如此)。

### 3.5 Flash 布局(F103RB,页 1 KB)

| 地址 | 大小 | 内容 |
|---|---|---|
| 0x0800_0000 | 16 KB | bootloader |
| 0x0800_4000 | 108 KB | 应用 |
| 0x0801_F000 | 1 KB | 应用记录(长度、CRC32),bootloader 写 |
| 0x0801_F400 | 2 KB | 设置(两页轮换，带序号 + CRC)|

bootloader 留在 DFU 等待重刷(设备在手边，可以接受)。

## 4. 总体架构

### 4.1 执行器与中断(P0 已实现)

单个 embassy 执行器 + 分级中断。最初设想的"中断执行器 + 线程模式阻塞工作者"没有采用：
把接触卡的字符接收放进中断后，协议层可以整体 async,更简单。

| 优先级 | 中断 | 内容 |
|---|---|---|
| P0 | EXTI9_5、EXTI15_10、USART2 | 接触卡字符接收、P5 模块帧、磁条时钟、模块 UART |
| P1 | SPI2(空闲外设当软中断)| 替 P0 处理程序唤醒任务 |
| P2 | USB、TIM4(embassy 时间)| |
| 线程 | 执行器 | 全部任务 |

- **接触卡字符层**(iso7816.rs):起始位下降沿进 I/O 线的 EXTI 中断，在中断里对着 DWT 采完整个字符、
  校验错时发错误信号(卡会重发)、入队；任务侧 async 等队列。发送一个字符关中断(默认速率约 1.1 ms),
  字符之间让出执行器。卡座 3 的 EXTI9 与磁条 2 轨共用，使用卡座 3 期间借走(期间刷卡 2 轨失效)。
- **临界区不屏蔽 P0**:`critical-section` 换成基于 BASEPRI 的实现(只屏蔽 P1 及以下),embassy 内部的
  临界区不再推迟起始位中断。实测前后对比：7.75 µs etu 的卡原来约 1/40 的 APDU 读错 SW2,改后 0/10000。
  代价:P0 处理程序只能用原子量，唤醒任务经 P1 软中断转交。
- **USART2 必须与 EXTI15_10 同在 P0**:模块发长应答时 PB15 也会反复拉高(不是帧)，每次进 EXTI15 约 50 µs;
  同优先级时中断号小的 USART2 先服务，放到 P1 被抢占就溢出(实测)。
- **长时间忙等里顺带服务磁条**:接触卡收发字符、P5 模块 I2C 收发期间轮询磁条 EXTI 挂起位，刷卡不丢位
  (实测：接触卡连续收发 10000 条 APDU 期间刷卡 4 次全部正确)。
- **实时锁**(rt.rs `RT_LOCK`):P5 模块命令与接触卡每次操作互斥(实测：5 次长模块命令期间接触卡 1200 条 APDU 无错)。

### 4.2 模块与所有权

```
          ┌──────── USB ────────┐
          │ IF0 CCID  IF1 HID  IF2 CCID │
          └──┬────────┬───────────┬──┘
   ┌─────────▼──┐  ┌──▼─────┐  ┌──▼──────────┐
   │ Contactless │  │ HID 输出 │  │  Contact    │  卡座 1–5,TIM3 时钟引用计数
   │ +idsam      │  │+厂商报告 │  └──────┬──────┘            卡座 1–5,TIM3 时钟引用计数
   └─────┬──────┘  └──▲─────┘         │
         │  Secure PIN │ 磁条/按键     │ Secure PIN
         └─────────────┼──────────────┘
                 ┌─────▼─────┐
                 │  PIN 服务   │◀── 键盘事件
                 └─────┬─────┘
                 ┌─────▼─────┐
  事件总线 ─────▶ │    UI      │──▶ 屏/字库、蜂鸣器
 (PubSubChannel)  └───────────┘
```

- 每个硬件只有一个所有者：THM3060 归 `Contactless`(含 idsam 中继);屏 / 字库总线归 UI 任务；
  蜂鸣器归 UI 任务(其他模块发事件，不直接响);键盘归键盘任务。
- **事件总线**(`embassy_sync::PubSubChannel`,深度 8):`CardIn/Out{slot}`、`Swipe{ok}`、`Key`、
  `HostActive{iface}`、`PinPrompt/PinDone`、`HostText` 等。UI 是唯一显示/发声的消费者。
- **实时锁**:`Mutex<CriticalSectionRawMutex, ()>`,idsam 命令期间与接触卡每次操作期间持有。

### 4.3 键盘的归属

键盘事件按当前模式分发：

| 模式 | 进入 | 按键去向 |
|---|---|---|
| 空闲(透明) | 默认 | 按下 / 松开原样转成 HID 键盘的按下 / 松开(见下表),自动重复交给主机 |
| PIN 输入 | 收到 `PC_to_RDR_Secure` | 只进 PIN 服务，屏显示星号；**不送 HID** |
| 主机读键 | 厂商报告"读按键" | 明文上报给主机(用于非敏感输入)|
| 菜单 | 长按 F1 2 s | 菜单任务 |

透明模式键位(与磁条输出同用美式布局主键盘区用法码，不受主机 NumLock 影响):

| 键 | HID 用法 | 键 | HID 用法 |
|---|---|---|---|
| 0–9 | 0x27, 0x1E–0x26(主键盘数字)| 确认 | 0x28 Enter |
| 取消 | 0x2A Backspace | F1–F3 | 不输出(F1 长按进菜单)|

- 进入 PIN 模式时若有键处于按下状态，先给主机发一次全部松开，避免主机端卡键。
- 按键与磁条共用报告 ID 1,两者都经同一个 HID 输出任务(`Channel`)串行发送，刷卡打字期间的按键排在后面。
- 透明模式下按键明文到主机是预期行为；需要保密的输入走 PIN 模式。

## 5. 子系统设计

### 5.1 CCID 公共部分

- 接口 0(非接)1 卡座，接口 2(接触)5 卡座(卡座 1 = 正面，2–5 = PSAM)。
- `bPINSupport = 0x03`(校验 + 修改),`wLcdLayout = 0x0410`(4 行 × 16 字),两个接口都声明。
- 新增消息:`PC_to_RDR_Secure`(0x69)、`PC_to_RDR_Abort`(0x72,配合类请求 ABORT)、
  `PC_to_RDR_Escape`(0x6B,先回 CMD_NOT_SUPPORTED,厂商功能统一走 HID)。
- `RDR_to_PC_NotifySlotChange` 多卡座：每卡座 2 位，5 卡座 = 2 字节位图。
- 短 APDU + 命令链；扩展 APDU 不做(RAM 不够，gpg/ykman 会自动改用命令链)。
- libccid 下一个接口多卡座会出现 "HD100 Contact 00 00 … 00 04" 五个读卡器。

### 5.2 PIN 输入(Secure)

流程(以 PIN 校验为例,CCID 6.1.11.4):
1. 解析 `abPINDataStructure`:超时、格式(bmFormatString:二进制 / BCD / ASCII,左右对齐、偏移)、
   PIN 块长度、长度字段位置(bmPINLengthFormat)、最小 / 最大位数、bEntryValidationCondition(确认键 / 满位数 / 超时)、
   bNumberMessage / bMsgIndex(选提示语)、APDU 模板。
2. 发事件 `PinPrompt{slot, msg}` → UI 显示 `Enter PIN`,键盘切到 PIN 模式。
3. 收集按键：数字追加、取消 → 中止，确认 → 结束；每键屏上加一个星号；达到最大位数自动结束(若条件允许)。
   超时 / 取消返回 CCID 错误 `0xF0`(超时) / `0xEF`(取消)。
4. 按格式把 PIN 填入 APDU 模板，经该卡座的正常 xfr 发给卡，应答原样返回主机。
5. 根据 SW 发 `PinDone{sw}`:9000 → `PIN OK`;63Cx → `Wrong PIN, x left`;其余 → `Failed SW xxxx`。
6. PIN 缓冲(栈上 ≤ 16 字节)用 `core::ptr::write_volatile` 清零。

修改 PIN(6.1.11.5)同理，按 bConfirmPIN / bInsertionOffsetOld/New 依次收旧 PIN、新 PIN、确认新 PIN,
提示语为 `Old PIN` / `New PIN` / `Confirm PIN`。

验证目标:`gpg --card-edit`(scdaemon 自动用 pinpad 校验 OpenPGP 卡)、OpenSC `pkcs11-tool --login`(pinpad)、
PC/SC `FEATURE_VERIFY_PIN_DIRECT` 直接调用。

### 5.3 接触卡

**多卡座**:`[Option<Card>; 5]` + 每卡座在位标志。TIM3 CH3 时钟按引用计数：座 2–5 任一有会话就保持输出，
全部结束才停。卡座 2–5 的冷复位不会碰共享时钟引脚模式，只动自己的 RST/I/O。

**在位检测**(无卡检测开关，只能冷复位探测):
- 卡座 1:空闲时每 500 ms 探测一次(同现在)。
- 卡座 2–5:开机、主机 IccPowerOn 时探测；空闲时每 10 s 轮流探测一个(PSAM 卡很少插拔)。
- 有会话的卡座从不探测；实时锁被占用时跳过本轮。

**协议**:
- T=1:块协议(I/R/S 块、IFSD 协商、WTX、链接、错误恢复)放在固件里，与 T=0 一样对外是短 APDU。
  ATR 里 T=0、T=1 都有时选第一个提供的协议(TD1 低 4 位)。
- PPS:保持现有选择逻辑；`MIN_ETU_CLOCKS = 16`(4 µs)按实测保留。

**后续可选优化**:卡座 1 收方向改用 USART3 RX 硬件接收(PB11 = USART3_RX,9 位偶校验)，省掉中断里采样的 CPU;
需实测 4 µs etu 下能否工作及错误信号时序。

### 5.4 非接

保持现有结构，改动：
- 用 `PubSubChannel` 发卡片放上 / 拿走事件，蜂鸣交给 UI。
- 多卡防冲突(位级冲突解析)— 低优先级。
- idsam 帧缓冲 2400 → 1400 B,串口环形缓冲 2048 → 512 B。

### 5.5 磁条

不变。刷卡结果发 `Swipe{ok}` 事件，UI 显示"刷卡成功 / 刷卡失败"(**不在屏上显示卡号**)。

### 5.6 UI(屏、蜂鸣器)

**全部英文界面**,只用字库的 ASCII 6×12(不依赖 GB2312 区)。风格和场景沿用 cardreader(hid2pcsc)给原厂固件下发的
状态面板(`cardreader/src/backend/huada/panel.rs`、`screen.rs`)。那边只能经原厂 0x69 命令按字符网格写
(20 列、半行为单位)，这里自己掌握帧缓冲，同样的场景可以做成像素级平滑移动。

**版面**:128×64,4 行 × 21 列，行距 16 px(字高 12 + 间隔 4),各行 y = 0 / 16 / 32 / 48。

| 行 | 待机内容 | 例 |
|---|---|---|
| 0 | 标题 + 右侧 USB 状态图标(已配置 / 挂起 / 未连接)| `HD100 v0.2` |
| 1 | 正面卡座:`CT` + ATR 十六进制(截断)/ `no card` / `card present` | `CT 3BFA1800FF1000003` |
| 2 | 非接:`RF` + UID 或 `no card` | `RF 04A1B2C3D4E5F6` |
| 3 | 提示 / 雷达脉冲;有 PSAM 时显示各座状态 | `  Tap a card )))` / `SAM 2:- 3:* 4:- 5:-` |

**场景**(与 cardreader 对应，参数相同):

| 场景 | 触发 | 内容 |
|---|---|---|
| wave | 开机 2 s | `HD100` 各字母沿行进正弦上下浮动(像素级，每 30 ms 一帧),底行副标题 `open firmware` |
| converge | wave 结束 | CT 行从顶上落下、RF 行从底部升起，标题从左边滑入、提示从右边滑入，停在完整面板 |
| typewriter | 新卡就位 | 对应行清空后带 `_` 光标逐字打出(60 ms / 字)|
| radar | 空闲且无卡 | 第 3 行 `Tap a card` 后面 `)` `))` `)))` 循环(200 ms / 步)；空闲 10 min 后停在静态面板 |
| toast | 刷卡、主机文字等 | 第 3 行反显横条显示 2 s(`Swipe OK` / `Swipe error` 等),再回原内容 |
| pin | PIN 输入 | 全屏:`Enter PIN` / 星号行(每键一个，带光标闪烁)/ `OK=confirm X=cancel`,结果显示 1.5 s |
| menu | 长按 F1 | 反显选中行;F2 / F3 上下，确认进入，取消返回 |
| update | bootloader | `Firmware update` + 进度条 |

规则(同 cardreader `screen.rs`):
- 状态变化时，正在播放的场景在下一帧边界放弃，直接进入新状态的画面；开机 wave 期间有卡就跳过 converge。
- 刷卡不在屏上显示卡号，不显示任何个人信息。
- PIN 输入优先级最高，打断任何场景；结束后回待机面板(不重播飞入)。

**实现**:
- `ui` 任务独占屏和字库总线；各模块只往事件总线发状态，从不直接写屏。场景是"帧生成器"(状态机，`next() -> Option<hold>`),
  不预先生成帧列表(no_std,无堆)。
- 帧缓冲 1 KB;每帧只刷新脏页。模拟 SPI 一页 128 字节约 0.4 ms,整屏约 3 ms,30 fps 余量充足；
  每页之间 `yield_now()`,不长时间占用高优先级执行器。
- 字形每次从字库 ROM 读(一个字约 50 µs),不在 RAM 缓存。
- 场景逻辑写成与硬件无关的纯函数(输入状态 + 时间 → 帧缓冲),可在主机上 `cargo test` 对帧缓冲断言，
  对应 cardreader 里对"玻璃模型"的单元测试。

**声音**:
- 蜂鸣器：插卡 / 放卡一声(50 ms),失败两声；设置里可关闭。
- 不用语音(太吵)。

### 5.7 厂商控制通道(HID 特性报告)

接口 1 增加特性报告(report ID 2–5),只走控制管道：

| ID | 方向 | 内容 |
|---|---|---|
| 2 | SET | 命令：显示文本 / 清屏 / 蜂鸣 / 进入读键模式 / 写设置 |
| 3 | GET | 上一条命令的结果、按键队列 |
| 4 | GET | 诊断计数(各卡座收发、错误、idsam 统计、看门狗复位次数、复位原因)|
| 5 | GET | 版本、构建信息、UID |

不提供软件进入 bootloader 的命令(防止主机端恶意刷机),只能物理按键进入。
上位机工具 `tools/hd100ctl.py`(hidapi)。

### 5.8 设置存储

两页 flash 轮换，记录 = 魔数 + 序号 + 长度 + 内容 + CRC32,启动取有效且序号最大的一页。
内容：屏对比度、提示音开关、数字键 HID 输出开关、PIN 输入超时上限。写入只在菜单 / 厂商命令时发生。

### 5.9 Bootloader

- USB DFU 1.1,PID 与应用不同(开发期 1209:0004)。
- 进入条件：上电时按住"取消 + 确认";或应用记录无效。屏显示"固件升级"与进度。
- 启动应用：校验记录里的 CRC 后，在外设未初始化的状态下跳转。
- 产品构建下 bootloader 停留时关 SWD;调试一律 BOOT0。
- 参考 bp8903-fw/boot(709 行)，去掉暂存区，加键盘扫描与屏显示。

### 5.10 可靠性

- IWDG 2 s,由高优先级执行器里的看门狗任务喂；任务还检查各关键任务的"心跳"计数，任一停止就不喂。
  调试器停核时 IWDG 暂停(DBGMCU_CR.DBG_IWDG_STOP)。
- panic → 产品构建复位，复位原因(RCC_CSR)计入诊断报告。
- WFI 睡眠前置 DBG_SLEEP(hardware.md 已记)。

## 7. 协处理器(后续)

先搁置，等命令表研究清楚(尤其 0x50/0x52/0x53/0x56 与密钥写入)。届时评估能否让输入更安全，例如：
- PIN 在键盘侧即由协处理器加密(PIN 块 + 3DES/其他),MCU 和主机都只见密文；
- 密钥只存协处理器、不可读出，用于设备认证或主机与读卡器之间的加密通道。
与本设计的接口点：PIN 服务(5.2)的"填入 APDU"一步，以及厂商通道(5.7)。在此之前 PC15 保持高电平。

## 8. 已定决策(2026-11-20)

1. 不用语音。产品构建(有 bootloader 后)开 `mute` 让芯片保持复位；调试构建保留 SWD,接受上电那一声。
2. bootloader 进入：上电时按住"取消 + 确认"。
3. 正式 USB VID/PID 以后再申请，开发期沿用 pid.codes 测试 PID。
4. 接触接口保持短 APDU 级，固件实现 T=1。
