# HD100 硬件说明

华大(Huada)HD-100 带屏密码键盘双界面读卡器的硬件资料。内容来自原厂固件静态分析、官方 SDK 与实机测量；
标"实测"的已在板上验证，"未确认"的会单独注明。

## 总览

| 部件 | 型号 / 实现 | 连接 |
|---|---|---|
| 主控 | STM32F103RBT6(LQFP64,128 KB flash / 20 KB RAM) | 8 MHz HSE ×9 = 72 MHz |
| USB | 片内 USB-FS,Type-B 口 P6 | PA11/PA12,D+ 上拉由 PC11 控制 |
| 非接 | 同方 THM3060(LQFP48,SPI 模式) | 模拟 SPI |
| 安全模块 P5 | 黑盒 SAM,多数机器未装 | USART2 + 模拟 I2C |
| 接触卡 | 正面卡座 JP1 + 4 个 PSAM 座，无专用读卡芯片 | GPIO 模拟 ISO 7816 |
| 磁条 | Singular M3-2200L 双磁道解码芯片，磁头 P3 | GPIO + 外部中断 |
| 键盘 | 15 键 | PB3–PB7 五线 |
| 屏 | 128×64 单色,ST7565 兼容(P1 排线) | 模拟 SPI |
| 字库 | 高通 GT21L16S2Y(SOP8) | 与屏共用总线 |
| 蜂鸣器 | 有源蜂鸣器 | PD2 |
| 语音 | 丝印磨掉的 SOP8 OTP 语音芯片 + 两线喇叭 | PA13/PA14(与 SWD 共用) |
| 协处理器 | 型号不明 | 与 THM3060 共用 SPI |

## 主控、启动与调试

- BOOT0(脚 60)经电阻接地，飞线到 3.3V 进系统 bootloader(SWD 在 bootloader 下始终可用)。
  PB2/BOOT1 接地。
- NRST(脚 7)原有对地大电容，会拖慢复位边沿，使 connect-under-reset 失效；拆掉后正常。
- 原厂固件开了读保护 RDP Level 1,并且关闭 SWD(PA13/PA14 让给语音芯片)。解除 RDP 会整片擦除。
- **SWJ_CFG**:键盘用到 PB3/PB4,磁条用到 PA15,必须设 SWJ_CFG=010(关 JTAG 留 SWD)才能当 GPIO 用。
- **实测:SWJ_CFG 设为 100(关 SWD)后再写回 010,SWD 不会恢复。**一旦固件动用 PA13/PA14,
  之后只能 BOOT0=1 进 bootloader 重新烧录。
- F1 系列在 WFI 睡眠时若未置 DBGMCU_CR.DBG_SLEEP,HCLK 会停，调试器访问 AHB-AP 卡死。

## USB

- D+ 1.5 kΩ 上拉经 PC11 门控，**低电平接通**(实测)。设备准备好后再拉低 PC11 才会枚举。
- 原厂枚举为 `072F:90D5`(借用 ACS 的 VID),单 HID 接口(EP1 IN 8 字节),无字符串描述符。

## 键盘(实测)

- 15 个键全部接在 PB3–PB7 五根线之间，每个交叉点串二极管，所以有方向，最多 5×4=20 个位置。
- 扫描：轮流把一根线推挽拉高，其余四根设为**下拉输入**(浮空不行，低电平过不了二极管)，读到高 = 按下。
- 键位(原厂键码，拉高线 → 读到线):

| 键 | 码 | 线 | 键 | 码 | 线 | 键 | 码 | 线 |
|---|---|---|---|---|---|---|---|---|
| 1 | 01 | PB3→PB6 | 6 | 06 | PB6→PB5 | F1 | 0B | PB3→PB7 |
| 2 | 02 | PB4→PB6 | 7 | 07 | PB3→PB4 | F2 | 0D | PB4→PB7 |
| 3 | 03 | PB5→PB6 | 8 | 08 | PB5→PB4 | F3 | 0E | PB5→PB7 |
| 4 | 04 | PB3→PB5 | 9 | 09 | PB6→PB4 | 取消 | 0C | PB4→PB3 |
| 5 | 05 | PB4→PB5 | 0 | 0A | PB5→PB3 | 确认 | 0F | PB7→PB3 |

  其余位置(0x10–0x13、PB6→PB3)板上没有键，原厂固件为多机型共用。

## 屏与字库(实测)

- LCD:ST7565 兼容控制器(132 列，显示 1..128),模拟 SPI。/CS=PA1, /RST=PA0, SCK=PC3, SDA=PC0, A0=PC2。
  命令高位先发，**显示数据低位先发**。页 p 对应控制器页 7−p,列 x 对应控制器列 x+1。
  初始化序列:`E2 2F 60 A0 C0 25 81 37 AF 23`(对比度 0x37 为原厂值)。
- 字库 GT21L16S2Y:/CS=PC1, SCK=PC3, SI=PC2, SO=PC0(读时切上拉输入),命令 `03` + 24 位地址。
  - 6×12 ASCII:基址 0x66D40,每字 12 字节。
  - 12×12 GB2312:`0x3CF80 + ((MSB−0xB0)·94 + (LSB−0xA1) + 376)·24`,只覆盖 MSB 0xB0..0xF7。
    **偏移是 376,不是手册写的 846**(实测)。
  - 字形为纵向字节：前 w 字节为上 8 行，后 w 字节低 4 位为下 4 行。

## 蜂鸣器与语音(实测)

- 蜂鸣器 PD2:有源，高电平响。原厂开机响 50 ms。
- 语音芯片：喇叭只接语音芯片，不接 MCU;语音固化在芯片内，不可改写。
  接口为复位 + 脉冲计数:RST=PA14, DATA=PA13。两线拉低 1 ms → RST 高 1 ms 后拉低 →
  N 个 DATA 脉冲(高 1 ms、低 1 ms)= 播第 N 段。
- 段号表(官方 SDK `ICC_DispSound`):

| 段 | 内容 | 段 | 内容 | 段 | 内容 |
|---|---|---|---|---|---|
| 01 | 请插卡 | 06 | 操作成功 | 0B | 请再次输入密码 |
| 02 | 请刷卡 | 07 | 操作超时 | 0C | 请输入新密码 |
| 03 | 读卡错误 | 08 | 操作失败 | 0D | 请输入旧密码 |
| 04 | 请输入密码 | 09 | 请取回卡 | 0E | 请确认新密码 |
| 05 | 密码错误 | 0A | 请重新输入密码 | | |

- 与 SWD 冲突:SWD 开着时 SWDIO 上拉、SWCLK 下拉，芯片看来就是"复位 + 1 个脉冲",所以上电会播一次"请插卡"。
  RST 持续拉高可让芯片保持复位(静音，实测)。想自定义声音只能改硬件(断开语音芯片，用空闲定时器 PWM 驱动喇叭)。

## 磁条(实测)

- Singular M3-2200L(同 M3-2200G,SOIC-28)双磁道 F2F 解码，接 ISO 第 2、3 轨，**只读**(无编码电路)。
- 2 轨：时钟 PA9 / 数据 PA8;3 轨：时钟 PC10 / 数据 PA15;/CLS = PA10(低 = 卡经过磁头)。
- 数据低电平 = 1,时钟下降沿采样。正反向刷卡均可解码,LRC 校验通过。

## 非接 THM3060(实测)

- SPI 模式:SS_N=PB1, SCLK=PC4, MOSI=PA6, MISO=PA5, RSTN=PC5;mode 0,高位先发，命令字节最高位 1 = 写、0 = 读，
  SCLK ≤ 2.5 MHz。上电检查：写 FCONB=0x05 能读回。
- 手册未写的行为：
  - **PSEL bit6 = 扩展模式开关**。PSEL=0x50 走扩展路径(写 0x1C=1 启动，轮询 0x14 ESTAT:0x10 完成、0x08 无应答、
    0x12 完成但 CRC 错),收到的数据带 2 字节 CRC_A 需软件校验，且约 32 字节以上的帧会丢 1 字节；
    PSEL=0x10 为普通 Type A,走标准路径，芯片校验并去掉 CRC。M1/防冲突/选卡用 0x50,ISO-DEP(RATS 起)用 0x10。
  - 0x13 AFRAME:0xC0 初始化，0x40 常规，0x46 防冲突帧(无 CRC),0x42 选卡及之后。
  - **隐藏的 Crypto1(M1 认证)**:明文发 `60/61 块号` 收 4 字节 nt → 0x15=0x08,nt 写 0x17..0x1A,
    0x16 依次写 6 字节密钥 + 4 字节 UID,读卡器随机数写 0x17..0x1A → 0x15=0x0C 启动，轮询 0x14,
    `(v & 0xEF) == 0` 成功 → 0x15=0x08、0x12=1 打开加密，之后的帧由芯片加解密。
    **每次认证前必须先写 0x15=0x00**,否则第二次认证一律失败。M1 写块的 4 位 ACK 在字节高 4 位(`0xA0`)。
- 不支持 ISO-DEP 的 Type B 卡(ATQB 的 PUPI 全 0):用固定 ATTRIB `1D 00000000 00 08 01 08`(回 `08`),之后为原始帧 + CRC_B。
- 实测可用:JavaCard(GP / OpenPGP / FIDO)、银联卡(PPSE)、YubiKey、CanoKey、M1、NTAG215。
- 射频余量偏小(未装机壳时),部分卡需贴近。

## 安全模块 P5(实测)

- 黑盒模块，需外部供电；没电时所有引脚被钳到地，别在没电时把 PA2/PC13 拉高(会反向供电)。
- 主机侧:USART2 115200 8N1,帧 `AA AA AA 96 69 | LEN(BE) | CMD PARA DATA | XOR`。
- 卡侧：模块没有射频，把每个射频帧交给 MCU 经 THM3060(Type B)转发，卡的应答 + 状态字节 00 写回模块。
  - 模块 → MCU:模块当 I2C 主机，拉高 PB15 的同时已发 START,**晚 500 µs 即丢帧**,必须在中断里接收。
    模块发长 UART 应答期间 PB15 也会反复变高但不发 START。
  - MCU → 模块:MCU 当主机,PC14 拉高期间写入。模块等应答的超时在 30–80 ms 之间。
  - SCL/SDA 用开漏即可(模块侧有上拉)。PC13 低 10 ms 复位模块。
- **背光闪烁(实测)**:模块运行时，若 MCU 在 I/O 突发(LCD 刷页、接触卡冷复位探测)之间进入睡眠(WFI/WFE),
  屏背光会随之可见地闪；同样的工作让 CPU 不睡眠就不闪，单纯的 CPU 忙碌突发也不闪；模块不运行时都不闪。
  模块刚放出复位的头几秒叠加开机动画的密集刷屏也会闪。机理未明(推测模块与背光共用的供电 / 地受扰)。
  固件对策：开机动画结束后才放出模块；检测到模块后 CPU 不再睡眠(多耗约 20 mA)。

## 接触卡 / PSAM(实测)

- 5 路全部由 STM32 GPIO 模拟 ISO 7816,I/O 与 RST 为开漏，外部上拉(较弱，释放后不要立刻回读)。
  卡 VCC 常供电，没有电源开关脚，也**没有卡检测开关**(实测：插拔卡时全部 GPIO 状态不变)——只能靠冷复位有无 ATR 判断在位。

| 卡座 | 位置 | I/O | RST | CLK |
|---|---|---|---|---|
| 1 | 正面卡座 | PB11 | PB12 | PA7(TIM3_CH2) |
| 2 | PSAM | PC7 | PC6 | PB0(TIM3_CH3,2–5 共用) |
| 3 | PSAM(实测 SIM) | PC9 | PC8 | PB0 |
| 4 | PSAM | PB13 | PB10 | PB0 |
| 5 | PSAM | PC12 | PB14 | PB0 |

- CLK:TIM3 PSC=0 ARR=17 → 4 MHz;停钟 = 引脚切回推挽输出低。1 etu(F=372, D=1)= 93 µs。
- 冷复位:RST 低、I/O 释放、开钟、≥400 时钟后 RST 高、收 ATR。**ATR 后需等 10 ms 再发第一条命令**(原厂同样如此)。
- 实测三种速率：默认 93 µs(银联卡)、特定模式 TA1=18 → 7.75 µs(NXP JavaCard)、PPS 协商到 4 µs(SIM 卡)。
- 未确认:PSAM 座 2/4/5 的物理位置与实卡验证；卡 VCC 电压等级。

## 协处理器(实测在位，用途部分确认)

板上还有一颗型号不明的协处理器，挂在 THM3060 的 SPI 总线上。原厂固件和官方 SDK 都没有实际使用它，本固件也不使用。
下面的命令表来自盲扫。

- 接线：与 THM3060 共用 SCLK=PC4 / MOSI=PA6 / MISO=PA5(mode 0,高位先发);片选 PC15,
  **每个字节一次 CS 脉冲，字节间隔 100 µs**;PA4 上拉输入为 READY,连续 3 次(1 ms 间隔)读到低 = 应答就绪。
  发送时 MISO 回显上一个字节。不用时保持 PC15 为高，即可与 THM3060 共用总线。
- 帧格式:
  - 请求 `AA BB | LEN(LE,= 1 + 数据长) | CMD | DATA | XOR(LEN..DATA) | BB`
  - 应答 `AA BB | STATUS | LEN(LE) | DATA | XOR(STATUS..DATA) | CC`,最长 560 字节，命令最多等 1500 ms。
- 状态码:00 成功;01 未知命令 / 子命令;02 长度或参数不对。
- 原厂固件只把主机 HID 命令 0xA6 的载荷原样透传给它，自己从不调用。
- 命令表(全零或简单数据试探):

| 命令 | 功能 | 依据 |
|---|---|---|
| 0x54 / 0x55 | DES / 3DES(2 字节参数 + 8 字节块) | 输出与 DES(密钥 FF×8)逐字节一致，块按小端字节序处理 |
| 0x51 | 16 字节分组密码(2 字节参数 + 16 字节块),算法未识别 | 与 AES 不符；参数改变输出 |
| 0x57 | SHA-1 | 子命令 00 返回 SHA-1 初始状态 67452301 EFCDAB89 98BADCFE 10325476 C3D2E1F0 |
| 0x59 / 0x5A | 设置类(1 字节参数) | 回 00,无数据 |
| 0x50 / 0x52 / 0x53 | 未知(需要特定参数) | 全零 1–512 字节均回 02;原厂对 0x50 不取应答数据 |
| 0x56 | 未知，耗时命令 | 原厂异步处理：发出后先回主机"处理中",完成后主动上报 |
| 0x10 / 0x58 | 未知 | 全零任意长度均回 01;原厂对 0x58 固定发 2 字节 |

- 密钥槽为擦除态 FF(原厂从未写入密钥)。

## 原厂主机协议(部分)

- 官方库 SSSE32.dll 以 33 字节(含报告 ID 0)读写：`00 02 | 08 00 | LEN(LE,含 CMD) | CMD | DATA | XOR`。
- 已知命令字:0x69 屏显示,0x6B 语音,0x6C 密码键盘输入(`ICC_GetInputPassSG`,开启按键扫描，按键明文上报),0xA6 透传给协处理器。
  官方 SDK 中还有 0x50–0x5A(SLE4442 存储卡)、0x64–0x66(外置键盘设置)等，原厂这版固件并不全部支持。
- 原厂固件含**无鉴权的 bootloader 擦除命令**,对原厂固件机盲扫 HID 协议可能把设备变砖。
